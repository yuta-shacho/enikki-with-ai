# CLI の設計

AI が絵日記と消費トークン量を送るための CLI の仕様をまとめる。AI がこのアプリを使う入口は、この CLI だけにする。CLI が呼ぶ API は [API の設計](api-design.md)、全体の構成は [システム構成](architecture.md) に書いてある。

## 1. 概要

| 項目         | 決めたこと                                                                       |
| ------------ | -------------------------------------------------------------------------------- |
| パッケージ名 | `enikki-cli`                                                                     |
| コマンド名   | `enikki`（`cli/package.json` の `bin`）                                          |
| 動く環境     | macOS と Linux。Node.js 22 以上（`engines` に書く）                              |
| 接続先       | 本番のサイト。開発のときだけ、環境変数 `ENIKKI_API_URL` で手元のサーバーに変える |

- Node.js はサポートが続いている LTS のうち、いちばん古い 22 に合わせる
- `ENIKKI_API_URL` は `http://localhost` か `http://127.0.0.1` を指す URL だけを受け付ける。ほかの値なら、通信せずに断る。ほかの URL を許すと、この環境変数を設定するだけで、API キーを好きなサーバーへ送らせることができてしまう

### コマンドの一覧

| コマンド               | 打つ人 | すること                                        | 呼ぶ API                                                          |
| ---------------------- | ------ | ----------------------------------------------- | ----------------------------------------------------------------- |
| `enikki login`         | 利用者 | API キーを設定する（2章）                       | `GET /api/v1/me`                                                  |
| `enikki submit`        | AI     | 絵日記を提出し、消費トークン量を記録する（3章） | `PUT /api/v1/enikki/today/{aiType}`、`PATCH /api/v1/token-usages` |
| `enikki install-skill` | 利用者 | AI に渡す skill を入れる（7章）                 | なし                                                              |

- `--help` と `--version` はどのコマンドでも使える
- 消費トークン量を送るだけのコマンドは作らない。別のコマンドにすると、AI が打ち忘れたときにその日の消費トークン量が記録されない。AI は skill の手順を毎回守るとは限らないので、`submit` の中で必ず送る

## 2. API キーの設定

### `enikki login`

```console
$ enikki login
API キーを貼り付けてください：
Taro さんの API キーを設定しました
```

1. 利用者が端末で実行する。標準入力が端末でないとき（Claude Code が実行したときや、パイプでキーを渡したとき）は、何も読まずに断る。Codex はコマンドに端末を割り当てられるので、この確かめでは断れない。Codex では skill の「`enikki login` を実行しない」に頼る
2. キーは画面に出さずに読む。コマンドの引数では受け取らない。シェルの履歴と AI の会話にキーが残らないようにするためだ
3. `GET /api/v1/me` を呼ぶ。`200` なら、キーを保存して利用者の名前を出す。`401` なら保存せず、キーが見つからなかったことを出す。つながらないときと `5xx` が返ったときも保存せず、キーを確かめられなかったことを出す
4. 画面でキーを作り直したときは、もう一度 `enikki login` を実行する。前のキーは上書きする

### 保存場所

| 項目           | 決めたこと                                                                      |
| -------------- | ------------------------------------------------------------------------------- |
| ファイル       | `$XDG_CONFIG_HOME/enikki/config.json`。`XDG_CONFIG_HOME` がなければ `~/.config` |
| 中身           | `{ "apiKey": "..." }`                                                           |
| パーミッション | ファイルは `600`、ディレクトリは `700`。持ち主だけが読める                      |

- `submit` は、このファイルからキーを読む。AI はキーを知らないまま提出できる
- OS のキーチェーンは使わない。Codex のサンドボックスの中からキーチェーンを読めるかがわからず、ネイティブのモジュールも増えるためだ。npm も `~/.npmrc` に認証のトークンを置いている
- AI もこのファイルを読める。そのため、このファイルを読まないことと、キーを会話に書かないことを skill に書く（7章）

## 3. 絵日記の提出

### 入力

```bash
enikki submit --ai claude_code --image ./enikki.svg --text-file ./enikki.txt
```

| オプション    | 必須 | 説明                                                    |
| ------------- | ---- | ------------------------------------------------------- |
| `--ai`        | 必須 | AI の種類。`claude_code` か `codex`。skill に書いておく |
| `--image`     | 必須 | 絵のファイルのパス。SVG、PNG、JPEG、WebP                |
| `--text-file` | 必須 | 文章のファイルのパス。UTF-8 として読む                  |

- 3つとも名前付きのオプションにする。AI がオプションの順番を変えても、同じように読める
- 文章はコマンドの引数で受け取らない。シェルを通すと、`"` のところで文章が切れたり、`$HOME` がパスに置きかわったりする。AI はファイルを書く道具を持っているので、文章をファイルに書けばシェルを通らない。`git commit -F` や `gh issue create --body-file` と同じ考え方だ

### 処理の順番

1. 入力を確かめる。ファイルがない、`--ai` の値が違う、文章が前後の空白を除くと空、のどれかなら、通信せずに断る
2. 2章のファイルから API キーを読む。なければ、通信せずに断る
3. sharp で絵を WebP にする（下の「絵の変換」）。変換できないときと、変換しても 5 MB を超えるときは、通信せずに断る
4. 消費トークン量を集計する（4章）
5. 絵日記を送る（`PUT /api/v1/enikki/today/{aiType}`）
6. 消費トークン量を送る（`PATCH /api/v1/token-usages`）。絵日記がハンコや値の誤りで断られたときも送る。送らないのは、5で3回送ってもサーバーにつながらなかったとき（時間切れを含む）、期限が過ぎたとき、送る記録がないとき（4章）だけにする
7. 結果を出す（5章）

絵日記を先に送るのは、絵日記がこのコマンドの本題で、サーバーにつながらないことにも早く気づけるためだ。

### 絵の変換

| 項目            | 決めたこと                                 |
| --------------- | ------------------------------------------ |
| SVG             | 長い辺が 2,048 px になる大きさで画像にする |
| PNG、JPEG、WebP | 長い辺が 2,048 px を超えるときだけ縮める   |
| WebP の品質     | sharp の既定（80）                         |
| メタデータ      | 消す                                       |

- 変換したあとに 5 MB を超えたら断る。長い辺が 2,048 px の WebP が 5 MB を超えることはまずないので、品質を下げて変換し直すことはしない

### 送り直しとタイムアウト

| 項目             | 決めたこと                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| 送り直すとき     | つながらない、返事が来ないまま時間切れになった、`5xx` が返った                                  |
| 送り直さないとき | `4xx` が返った。同じリクエストには、何回送っても同じ答えが返る                                  |
| 1回の待ち時間    | 20秒。期限までの残りが20秒より短ければ、残りの時間まで                                          |
| 送る回数         | API ごとに全部で3回まで。送り直す前に、1秒、2秒と待つ                                           |
| 期限             | コマンドを始めてから90秒。過ぎたら送り直さずに、まだ送れていない API を時間切れとして結果を出す |

- 2つの API はどちらも冪等で、同じものを送り直しても結果は変わらない。時間切れのあとでサーバーが書き終えていたときも、安全に送り直せる。ただし、0時の直前に出した絵日記を0時をまたいで送り直すと、2つの日に1件ずつ絵日記ができる（[API の設計](api-design.md) の5章）。0時の前の90秒に出したときにしか起きないので、防がない
- 期限があるので、どの場合も90秒で終わる。1つ目の API の3回目の返事が20秒ぎりぎりで来ると、2つ目の API は約63秒後に送り始め、残りの約27秒で打ち切る。期限がないと、2つ目の API にも最大63秒かかり、合わせて約126秒になる
- サーバーにまったくつながらないときは、1つ目の API に 20秒 × 3回 + 1秒 + 2秒 = 63秒かかり、2つ目は送らずに終わる
- 期限はコマンドを始めたときから数えるので、絵の変換と集計の時間も90秒に入る

期限を90秒にするのは、Claude Code がコマンドを既定で2分まで待つためだ。2分を過ぎると、Claude Code はコマンドを止めずにバックグラウンドへ移し、AI はその場で結果を読めない。skill では待つ時間を3分にするが、AI が skill を守らなかったときも、2分より手前で結果が返るようにする。

Codex はコマンドを既定で10秒、長くても30秒まで待ち、終わらなければコマンドを動かしたまま途中の出力を AI に返す。この CLI は30秒より長くかかることがあるので、Codex 用の skill に待ち方を書く（7章）。

## 4. 消費トークン量の集計

### 範囲

- 日本時間の今日を含む、直近7日分を送る
- Claude Code と Codex の両方の記録を読み、読めた AI の分をすべて送る。`--ai` の AI だけに絞らない。片方の AI でしか提出しない利用者でも、もう片方のグラフが埋まる
- 記録のない日は送らない。0 を送ると、本当に使わなかった日と区別できなくなる
- 送る記録が1件もないときは、`PATCH` を呼ばない。API は `usages` を1件以上としている。2つの AI のどちらにも直近7日の記録がないときと、どちらの記録も読めないときに起きる

### 読むファイル

| AI          | 読むファイル                                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------------------------------ |
| Claude Code | `${CLAUDE_CONFIG_DIR:-~/.claude}/projects/` の下の `*.jsonl` すべて。サブエージェントの `subagents/*.jsonl` も含む |
| Codex       | `${CODEX_HOME:-~/.codex}/sessions/` と `archived_sessions/` の下の `rollout-*.jsonl`                               |

- 更新日時が範囲の始まり（日本時間の6日前の0時）より前のファイルは読まない。そのあと書きこまれていないので、範囲の中の行はない
- Codex は再開したセッションを元のファイルに書き足すので、ディレクトリの日付ではなく行の時刻で日を決める
- Codex は更新日時から7日以上たったファイルを `.jsonl.zst` に圧縮し、元の更新日時を付け直す。こうしたファイルは上の決まりでいつも読まないので、`.jsonl.zst` は読まない。Codex が7日より早く圧縮するようになったら、`.jsonl.zst` も読む

### 行の読み方

日付はどちらも行の `timestamp`（UTC）に9時間を足した日付にする。

| 項目                                     | Claude Code                                         | Codex                                                               |
| ---------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------- |
| 読む行                                   | `type` が `assistant` で、`message.usage` がある    | `type` が `token_usage_record`                                      |
| 重複の除き方                             | `message.id` と `requestId` の組が同じ行は1つにする | `payload.response_id` が同じ行は1つにする                           |
| 入力（`inputTokens`）                    | `input_tokens`                                      | `input_tokens` − `cached_input_tokens` − `cache_write_input_tokens` |
| キャッシュ書き込み（`cacheWriteTokens`） | `cache_creation_input_tokens`（ないときは 0）       | `cache_write_input_tokens`                                          |
| キャッシュ読み込み（`cacheReadTokens`）  | `cache_read_input_tokens`（ないときは 0）           | `cached_input_tokens`                                               |
| 出力（`outputTokens`）                   | `output_tokens`                                     | `output_tokens`。reasoning の分を含む                               |

- 重複は読んだファイルすべてを通して除く。同じ組がほかのファイルに出ても1つにする。同じ組の行の時刻が0時をまたぐときは、いちばん早い時刻で日を決める
- Claude Code は1つの応答を内容のブロックごとに別の行に書き、どの行にも同じ usage を入れる。重複を除かないと、出力が約2.5倍になる（#9）
- Codex の `input_tokens` はキャッシュの分を含むので、Claude Code とそろえるためにキャッシュの分を引く
- 古い Codex の記録には `token_usage_record` がなく、その分は数えない

### 読めなかったとき

| 起きたこと                               | 動き                                                                               |
| ---------------------------------------- | ---------------------------------------------------------------------------------- |
| AI のディレクトリがない                  | その AI は使っていないとみなし、送らない                                           |
| ファイルを1つでも開けない                | その AI の分は全部送らない。一部だけを足すと少なく出て、正しい値を上書きしてしまう |
| 行が JSON として読めない、要る項目がない | その行を飛ばす（[システム構成](architecture.md) の6章）                            |

## 5. 出力とエラー

### 出力の形

CLI は絵日記と消費トークン量の結果を1行ずつ、日本語で標準出力に出す。終了コードが `1` のときは、「次にすること」の1行も出す。通信する前に断ったときは、断った理由の1行と「次にすること」の1行だけを出す。読むのは AI なので、JSON ではなく文にする。失敗の理由も標準出力に出し、行の順番が入れかわらないようにする。

```console
$ enikki submit --ai claude_code --image ./enikki.svg --text-file ./enikki.txt
絵日記：2026-11-10 の絵日記を出しました
消費トークン量：Claude Code と Codex の直近7日分を送りました
```

```console
$ enikki submit --ai claude_code --image ./enikki.svg --text-file ./enikki.txt
絵日記：出せませんでした。2026-11-10 の絵日記には、もうハンコが押されています
消費トークン量：Claude Code と Codex の直近7日分を送りました
次にすること：送り直さずに、この結果を利用者に伝えてください
```

| 終了コード | 意味                                                                         |
| ---------- | ---------------------------------------------------------------------------- |
| `0`        | 絵日記を出し、消費トークン量も送れた。送る記録がなくて送らなかったときも含む |
| `1`        | それ以外。「次にすること」の行を出す                                         |

- 記録を読めなかった AI があるときは、ほかの AI の分を送れても `1` にする

### 「次にすること」

CLI はレスポンスの `type` でエラーを見分ける（[API の設計](api-design.md) の4章）。AI がすることは、「利用者に頼む」「直して出し直す」「送り直さずに利用者に伝える」の3つに分かれる。

| 起きたこと                                                                                                      | 次にすること                                                                      |
| --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| API キーがない、`missing-api-key`、`invalid-api-key`                                                            | 利用者に、端末で `enikki login` を実行してもらう                                  |
| ファイルがない、`--ai` の値が違う                                                                               | コマンドを直して、出し直す                                                        |
| 絵を変換できない、変換しても 5 MB を超える、`invalid-image`、`image-too-large`                                  | 絵を描き直して、出し直す                                                          |
| 文章が空、`invalid-text`                                                                                        | 文章を直して、出し直す                                                            |
| `400`、`unknown-ai-type`、`invalid-token-usages`、知らない `type`                                               | 送り直さずに、結果を利用者に伝え、`npm i -g enikki-cli@latest` で更新するよう頼む |
| `enikki-stamped`、3回送ってもつながらない、期限が過ぎた、3回送っても `5xx` が返る、記録を読めなかった AI がある | 送り直さずに、結果を利用者に伝える                                                |

- 「次にすること」は1行だけ出す。2つ以上に当たるときは、表の上の行を選ぶ。たとえば、絵日記が `invalid-image` で断られ、消費トークン量が `5xx` で送れなかったときは、絵を描き直して出し直す。出し直せば、消費トークン量も送り直される
- 断られたときは、レスポンスの `detail` も結果の行に書く。`invalid-text` なら、文章が空なのか長すぎるのかが AI にわかる
- 消費トークン量の行には送れた AI、記録を読めなかった AI、送れなかった理由を書く
- 成功したときは、`201` なら「出しました」、`200` なら「書きかえました」と出す。ただし、送り直したあとの `200` は「出しました」と出す。前の回でサーバーが書き終えていたなら、初めての提出でも `200` が返るためだ
- API キーはどの出力にも出さない

## 6. 配布と更新

```bash
npm i -g enikki-cli       # 入れる
enikki login              # API キーを設定する
enikki install-skill      # skill を入れる

npm i -g enikki-cli@latest && enikki install-skill   # 更新する
```

- 更新したあとは `enikki install-skill` を実行し直し、skill も新しくする
- 新しいバージョンが出たことを知らせる仕組みは作らない。古い CLI からの提出も API が受け付ける（[API の設計](api-design.md) の6章）
- sharp は OS ごとのビルド済みのバイナリが npm から入るので、利用者のマシンではビルドしない
- npm への公開の手順は #13 で決める

## 7. AI に渡す skill

### 置き場所

| AI          | リポジトリの中                      | `enikki install-skill` が入れる先                |
| ----------- | ----------------------------------- | ------------------------------------------------ |
| Claude Code | `cli/claude/skills/enikki/SKILL.md` | `${CLAUDE_CONFIG_DIR:-~/.claude}/skills/enikki/` |
| Codex       | `cli/codex/skills/enikki/SKILL.md`  | `~/.agents/skills/enikki/`                       |

- skill は npm のパッケージに入れて配る
- `enikki install-skill` は、`${CLAUDE_CONFIG_DIR:-~/.claude}` があれば Claude Code に、`${CODEX_HOME:-~/.codex}` があれば Codex に skill をコピーする。4章で記録を読む場所と同じ環境変数を見る。前に入れた skill は上書きする
- 入れる先の `enikki` がシンボリックリンクのときは、上書きせずに断る。`~/.claude/skills/enikki` が `~/.agents/skills/enikki` へのリンクだと、2つの AI の skill が同じ場所に入り、あとに入れたほうだけが残る
- リンクではなくコピーにする。npm から CLI を消したときに、リンク先のないリンクが残らない

### 中身

| 項目         | 書くこと                                                                                                                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| いつ使うか   | 利用者が今日の絵日記を頼んだとき                                                                                                                                                                          |
| 文章         | その日の会話から、AI の目線で書く                                                                                                                                                                         |
| 絵           | 描き方は #21 に沿う。Claude Code は SVG を書く。Codex は `image_gen` が使えればそれを使い、使えなければ SVG を書く                                                                                        |
| ファイル     | 絵と文章は一時ディレクトリに書き、利用者のリポジトリに置かない。`image_gen` の PNG は、保存された場所（`$CODEX_HOME/generated_images/`）のパスをそのまま `--image` に渡す                                 |
| 提出         | `enikki submit --ai <AI の種類> --image <絵> --text-file <文章>` を実行する。Claude Code では、コマンドを待つ時間を3分にする。Codex では、`yield_time_ms` を 30000 にし、最初から通信の許可を求める       |
| 待ち方       | 結果が出る前にコマンドが返ってきたら、終わるまで待って結果を読む。Claude Code がバックグラウンドへ移したときは出力のファイルを読み、Codex が session ID を返したときは `write_stdin` で待つ。出し直さない |
| 結果         | 終了コードが `1` なら、「次にすること」の行のとおりにする。自分で送り直さない                                                                                                                             |
| 見つからない | `enikki` が見つからないときは、自分で入れずに利用者に伝える。Node.js のバージョンを切り替える道具を使っていると、ほかのプロジェクトでは見つからないことがある                                             |
| しないこと   | `enikki login` を実行しない。`~/.config/enikki/config.json` を読まない。API キーを会話に書かない                                                                                                          |

- Codex の既定のサンドボックスは外への通信を止めるので、Codex 用の skill には提出のときに通信の許可を求めることを書く（#21）

## 8. ほかの設計との関係

| 設計                               | 合わせたこと                                                                                                                                                                                                                                                                                                                               |
